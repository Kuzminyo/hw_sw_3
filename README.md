# Домашнє завдання #3

Дві програми на Python: сортування файлів за розширеннями (потоки) та пошук дільників чисел (процеси). Зовнішніх залежностей немає, потрібен лише Python 3.

## Частина 1. Сортування файлів (потоки) — `sort_files.py`

Рекурсивно обходить директорію-джерело й копіює кожен файл у піддиректорію цільової директорії, названу за розширенням файлу.

### Запуск

```bash
python sort_files.py <джерело> [призначення]
```

Якщо призначення не вказано, використовується `dist`.

Приклад:

```bash
python sort_files.py picture dist
```

### Як це працює

- Використовується один `ThreadPoolExecutor` (8 потоків).
- Кожна піддиректорія обробляється окремою задачею (`process_dir`), яка в свою чергу ставить у пул задачі для вкладених піддиректорій.
- Кожен файл копіюється окремою задачею (`copy_file`), тобто обхід каталогів і копіювання виконуються паралельно.
- Розширення береться в нижньому регістрі; файли без розширення потрапляють у `no_extension`.
- Якщо файли з однаковим іменем зустрічаються в різних директоріях, другий отримує суфікс (`name_1.ext`, `name_2.ext`), щоб нічого не перезаписалося. Резервування імені виконується під `Lock`, щоб потоки не конфліктували.
- Якщо цільова директорія лежить усередині джерела, вона пропускається під час обходу.
- Помилки доступу до файлів чи директорій логуються й не зупиняють програму.

### Перевірка

Тимчасове дерево з вкладеними папками (`picture/x.jpg`, `picture/icons/x.jpg`, `picture/Other/Icons/1600.png`, `picture/ibm.svg`) дало:

```
dist/jpg/x.jpg
dist/jpg/x_1.jpg
dist/png/1600.png
dist/svg/ibm.svg
```

## Частина 2. Факторизація (процеси) — `factorize.py`

`factorize(*numbers)` повертає для кожного числа список усіх його дільників без залишку, відсортований за зростанням.

### Запуск

```bash
python factorize.py
```

Скрипт перевіряє обидві версії тестом із завдання, а потім вимірює час.

### Реалізації

- `factorize_sync` — послідовна версія: цикл по числах, для кожного перебір `i` від 1 до √n; кожен знайдений дільник додає пару `i` та `n // i`.
- `factorize` — паралельна версія: той самий алгоритм, але числа розподіляються між процесами через `ProcessPoolExecutor(max_workers=cpu_count())`.

### Результати замірів

Машина: `cpu_count() = 16`.

Набір чисел: `128, 255, 99999, 10651060` та вісім чисел від `10**13 + 37` до `10**13 + 53`.

| Версія | Час |
|---|---|
| Синхронна | 2.243 с |
| Паралельна (16 процесів) | 1.050 с |

Прискорення приблизно 2.1 раза.

З меншим набором чисел (`128, 255, 99999, 10651060, 106510600, 212345678, 312345678, 412345678`) картина протилежна:

| Версія | Час |
|---|---|
| Синхронна | 0.006 с |
| Паралельна | 0.397 с |

### Висновок

Багатопроцесність виграє лише тоді, коли обчислень достатньо багато. На малих числах час витрачається на запуск процесів і передачу даних між ними, тому синхронна версія швидша. Прискорення також обмежене тим, що чисел у наборі лише 12: найважчі числа обробляються по одному в окремих процесах, і вся задача триває стільки, скільки найдовша з них.

Результати залежать від машини й навантаження на неї, тому абсолютні значення при повторному запуску відрізнятимуться.
